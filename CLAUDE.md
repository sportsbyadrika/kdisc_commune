# CLAUDE.md — Commune Workspace Management System

Guide for anyone (human or AI agent) extending this codebase. **Read `docs/PROJECT_OVERVIEW.md` first** — it is the
product spec (sections are referenced below as "spec §N").

Plain PHP 8.4 + MySQL 8.4 + Tailwind CSS v4 + Alpine.js. No framework: a small in-house micro-framework lives in
`app/Core`. Keep it small, explicit and boring.

## Quick start (local)

```bash
composer install
npm install && npm run build            # vendor JS + icons + CSS (output is committed)
cp .env.example .env                    # set DB_*; php bin/console key:generate → APP_KEY
php bin/console migrate:fresh --seed    # full schema + Kottarakara seed data
php -S 127.0.0.1:8000 -t public public/index.php
```

Test DB from scratch (MariaDB/MySQL):

```bash
mysql -e "CREATE DATABASE commune CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
          CREATE USER 'commune'@'localhost' IDENTIFIED BY 'commune';
          GRANT ALL ON commune.* TO 'commune'@'localhost';"
```

Seeded staff logins (password `Password@123`): `reception@commune.test`, `manager@commune.test`,
`finance@commune.test`, `stateadmin@commune.test`.

Checks to run before committing:

```bash
composer test          # PHPUnit (tests/Unit)
composer lint          # php -l over every PHP file
composer analyse       # PHPStan level 6 (phpstan.neon) — keep it at 0 errors
npm run build:css      # whenever you add/change Tailwind classes in views
```

## Request lifecycle

`public/index.php` → `App::boot()` (Dotenv, config, container bindings) → `App::handle()`:

1. Starts the **staff** session (cookie `commune_staff`, path `/staff`) for `/staff*` URLs, otherwise the **site**
   session (cookie `commune_session`). See `config/session.php`. Guards: `auth('staff')`, `auth('visitor')`.
2. `Router::dispatch()` runs global middleware (`csrf`) + route middleware, then the controller action.
3. Exceptions become responses in `ErrorHandler` (validation → redirect back with errors; `HttpException` →
   `resources/views/errors/{status}.php`; others → 500, or a detailed trace page when `APP_DEBUG=true`).
4. Security headers from `config/security.php` (CSP etc.) are added to every response.

## How to …

### Add a route
Pick the file by audience: `routes/site.php`, `routes/portal.php`, `routes/staff.php`.

```php
// routes/staff.php, inside the auth.staff group (names get the "staff." prefix automatically)
$r->get('/visitors/{id:\d+}', [VisitorController::class, 'show'])->name('visitors.show')->middleware('can:visitors.view');
$r->post('/visitors', [VisitorController::class, 'store'])->name('visitors.store')->middleware('can:visitors.register');
```

- Clean URLs only — never link to `*.php`. Generate URLs with `url('staff.visitors.show', ['id' => 5])`; extra
  params become the query string. Literal paths: `url('/pricing')`.
- Params: `{id}` or with inline regex `{id:\d+}` (no `{}` quantifiers inline — use `->where('id', '\d{4}')`).
- HTML forms can send `PUT/PATCH/DELETE` via `<?= method_field('DELETE') ?>`.
- `php bin/console routes` lists everything.
- Every staff route MUST sit in the `auth.staff` group and declare `can:<ability>` (preferred) or `role:<roles>`.
  Abilities live in `App\Enums\StaffRole::abilities()` — add new ones there.
- Staff sidebar entries are in `config/navigation.php`; an entry whose route does not exist yet shows as "Soon",
  so add the route name there when you build the feature.

### Add a controller
`app/Controllers/{Site|Portal|Staff}/ThingController.php`, `final class … extends Controller`.
Constructor and action parameters are autowired (services, `Request`, `Session`); route params are injected by name
and cast to `int`/`float`/`bool` when type-hinted. Return a `Response` (`$this->view()`, `redirect()`,
`Response::json()`, `Response::file()`/`download()`); returning an array produces JSON.
Keep controllers thin — put queries and rules in `app/Services/*`.

### Add a view
Views are plain PHP in `resources/views`, referenced as `'staff/visitors/show'`.

```php
<?php
/** @var App\Core\Template $this  @var array<string, mixed> $visitor */
$this->layout('layouts/staff', ['title' => 'Visitor', 'breadcrumb' => [['Dashboard', url('staff.dashboard')], ['Visitor']]]);
?>
<?php $this->start('actions') ?><a class="btn btn-brand" href="…">Edit</a><?php $this->stop() ?>
<h2><?= e($visitor['name']) ?></h2>
<?= $this->component('badge', ['label' => $status->label(), 'tone' => $status->tone()]) ?>
```

- Layouts: `layouts/site` (public), `layouts/staff` (console, sidebar), `layouts/auth` (split sign-in), all on
  `layouts/base`. Sections: `content` (default), `head`, `scripts`, `actions` (staff title bar).
- `$this->partial('path', $extra)` shares page data; `$this->component('name', $props)` is isolated.
  Components with a body: `$this->begin('modal', [...]) … <?= $this->end() ?>` (body arrives as `$slot`).
- Components (`resources/views/components`): `button`, `badge`, `alert`, `chips`, `card`, `input`, `select`,
  `textarea`, `checkbox`, `table`, `modal`, `stat`, `empty`, `breadcrumb`, `page-hero`, `facility-tile`.
  Each file documents its props at the top — reuse them rather than re-styling.
- Views must not run SQL or instantiate services; pass data from the controller.

### Escaping (mandatory)
- `<?= e($value) ?>` for **every** untrusted value, in text and attributes. `e()` handles enums and null.
- Only echo raw HTML that the code itself produced (`icon()`, `csrf_field()`, component output, `attrs()`).
- JSON for Alpine/JS: `<?= e(json_encode($data)) ?>` inside an attribute.
- SQL: always bound parameters via `db()`/`Database` methods. Identifiers go through `quoteIdentifier()`.

### Forms, CSRF, validation, flash
```php
<form method="post" action="<?= e(url('contact.submit')) ?>">
    <?= csrf_field() ?>                       // REQUIRED — the global csrf middleware returns 419 otherwise
    <?= $this->component('input', ['name' => 'email', 'label' => 'Email', 'type' => 'email', 'required' => true]) ?>
</form>
```
```php
public function store(Request $request): Response
{
    $data = $this->validate($request, [
        'email' => 'required|email|max:190|unique:accounts,email',
        'type'  => ['required', CustomerType::rule()],
        'start' => 'required|date|after_or_equal:today',
    ], [], ['start' => 'start date']);          // throws → redirect back with errors + old input
    // …
    return redirect(url('staff.visitors.show', ['id' => $id]))->with('success', 'Visitor registered.');
}
```
- Form components show `old()` values and `errors('field')` automatically; the flash partial (in every layout)
  shows `success|error|warning|info` messages and an error summary.
- XHR/`fetch` calls: send `X-CSRF-TOKEN: Commune.csrf()` (see `resources/js/app.js`), `Accept: application/json`
  to get 422 JSON validation errors.
- Rules: see the docblock in `app/Core/Validator.php`. Custom rules: `Validator::extend('aadhaar', fn ($v) => …,
  'Enter a valid Aadhaar number.')` (register in a service provider-like spot, e.g. the service that needs it) or
  inline closures returning `true` or an error string.

### Add a migration
`php bin/console make:migration create_things_table` → edit the new `database/migrations/*.sql`.
- Target **MySQL 8.4** syntax (tested on MariaDB 10.11 too): InnoDB, `utf8mb4_unicode_ci`, `BIGINT UNSIGNED` ids,
  `DATETIME` timestamps with defaults, named `fk_*`/`idx_*`/`uq_*` constraints, `VARCHAR` for enum-like columns
  (values validated by `app/Enums`), `DECIMAL(12,2)` money, `DECIMAL(6,3)` map percentages.
- Separate statements with `;` at end of line; no `;` at line end inside string literals.
- Never edit a migration that has run anywhere shared — add a new `ALTER TABLE` migration.
- `php bin/console migrate` (pending only), `migrate:fresh --seed` (dev reset), `migrate:status`.

### Add middleware
Implement `App\Core\Middleware` (`handle(Request $r, Closure $next, string ...$params): Response`), register an alias
in `config/middleware.php`, use as `'alias'` or `'alias:param1,param2'`.

### Add a seeder
`database/seeds/ThingSeeder.php` in namespace `Database\Seeds`, extend `App\Core\Seeder`, make it idempotent, add it
to `DatabaseSeeder::run()`. Run one: `php bin/console db:seed --class=ThingSeeder`.

## Conventions

- `declare(strict_types=1);` everywhere; `final` classes by default; constructor property promotion; typed props.
- Naming: controllers `ThingController`, services by capability (`PriceResolver`, `SeatHoldService`), route names
  `area.resource.action` (`staff.visitors.create`), tables plural snake_case, views snake/kebab paths.
- Rows are associative arrays. Use enums for statuses: `BookingStatus::from($row['status'])->label()/tone()`.
- Business rules belong to enums/services, not views (e.g. `SeatCategory::wholeUnitOnly()`,
  `PriceResolver::forSeat()` implements seat ?? zone ?? category rate, spec §5.5).
- Money: `DECIMAL` in DB, `money($amount)` to display (Indian grouping, ₹). Dates: `format_date()`.
- Settings (GST, prefixes, hold minutes): `setting('gst_rate')` from the `settings` table.
- Audit anything touching money, pricing, layout, KYC documents: `AuditLog::record('rate.update', 'rate', $id, $old, $new)`.
- Map coordinates are **percentages** of the floor image (`x_pct/y_pct` = top-left, `w_pct/h_pct` = size).
  Use `App\Services\Space\GridLayout` helpers. Cabins/rooms are parent `seats` rows with child chairs.
- Only published `layout_versions` count for inventory/availability.
- Uploads (KYC) go under `storage/uploads` and are streamed by an authorised controller with `Response::file()`.
- Logging: `logger()->info('Booking {no} approved', ['no' => $no])` → `storage/logs/app-YYYY-MM-DD.log`.

## Front-end

- **Tailwind v4, CSS-first.** All brand values are tokens in the `@theme` block of `resources/css/app.css`
  (`brand-*`, `accent-*`, `surface`, `ink`, `muted`, `line`, `seat-*`, fonts, radii, shadows). They are placeholders
  until K-DISC confirms branding — never hard-code hex colours in views; add a token instead.
  Reusable classes (`btn`, `chip`, `card`, `badge-*`, `input`, `table`, `seat-*`, …) are in `@layer components`.
- Build: `npm run build:css` (minified) / `npm run watch:css`. **Commit `public/assets/css/app.css`** — production has
  no Node.
- `npm run vendor:js` copies Alpine, Panzoom and Chart.js into `public/assets/vendor/`, copies `resources/js/*.js`
  to `public/assets/js/`, and regenerates `resources/icons/*.svg` from the `ICONS` list in `bin/vendor-js.mjs`
  (add a Lucide icon name there, re-run, then use `icon('name', 'size-5')`). Commit the outputs.
- **No CDNs.** Every script/style is self-hosted (CSP enforces it); only Google Fonts CSS is external, with
  system-font fallbacks.
- Alpine: register reusable components in `resources/js/app.js` via `Alpine.data()`/`Alpine.store()`.
  Standard Alpine build needs `'unsafe-eval'` in CSP (already configured). Don't put `<script>` inline — CSP blocks it.
  Content inside a sticky/blurred header that must be `position: fixed` needs `x-teleport="body"`.
- Placeholder imagery: `public/media/building.svg`, `floor-*.svg` (regenerate with
  `php bin/make-placeholder-plans.php` — drawn from the seed layout so desks align with seats), `space-*.svg`.
  Paths are stored in the DB (`buildings.photo_path`, `floors.photo_path`, `seat_categories.image_path`);
  swap in real photos by changing the DB value.
